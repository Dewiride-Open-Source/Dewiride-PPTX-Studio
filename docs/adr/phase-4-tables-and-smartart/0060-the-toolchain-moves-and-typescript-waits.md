# 0060 — The toolchain moves, and TypeScript waits

Date: 2026-09-27
Status: **accepted** — every root toolchain version is current except TypeScript, whose trigger has
not fired, and Playwright, which moves on its own. Two of the pins were security fixes. tsdown 0.23
changed the published declarations, and the website's API reference reads the new shape byte for
byte as it read the old.

**Maintenance after 4.1 · supersedes the version headings of
[0001](../phase-0-foundation/0001-toolchain.md) (Vitest 4.1.11, tsdown 0.22.14, Turborepo, pnpm
11.6.0), whose decisions stand.**

All three grouped PRs failed every job at install with `ERR_PNPM_OUTDATED_LOCKFILE`. This is
dependabot-core#16311: its peer probe runs `pnpm update … --lockfile-only` without `--no-save`,
which rewrites the root manifest's `catalog:` to a literal. The lockfile it writes then disagrees with
the `package.json` that is actually committed. It was fixed by dependabot-core#16317, merged
2026-09-23, after these PRs were generated. The lockfile here was regenerated by pnpm itself, and
all 71 importer specifiers still read `catalog:`.

## TypeScript stays at 6.0.3

0001's trigger is a typescript-eslint release whose peer range admits `^7`. On 2026-09-27, 8.70.1
(latest) and 8.70.2-alpha.10 (canary) both still declare `typescript: >=4.8.4 <6.1.0`. And
`typescript@7.0.2` exports only `version` and `./unstable/*`, with none of the compiler API that
typescript-eslint and `website/prerender/reference.mjs` call.

Dependabot now ignores TypeScript majors for `/` and `/website`, with the trigger named beside the
rule. Otherwise it reopens the refused bump every week inside a group that also carries everything
else.

## Two pins were vulnerabilities

- **pnpm 11.6.0 → 11.27.1.** 11.6.0 was in range for six high-severity advisories:
  GHSA-c59q-g84q-2gj5, -vq4v-j7r6-jq4m, -vx52-2968-3vc6, -qrv3-253h-g69c, -72r4-9c5j-mj57 and
  -fr4h-3cph-29xv. The last of them was fixed in 11.11.0.

  11.27.1 is npm's `latest-11`. 11.28.0 is still `next-11`, and its own security fixes cover a
  custom `modulesDir`, `userAgent` placeholders, Nix shims and shell completion, none of which this
  repository uses. `engines.pnpm` is `>=11.11.0`, so a vulnerable pnpm is refused.

- **Node 24.15.0 → 24.21.0** (`.nvmrc`, every CI job and the release). The security releases since
  were 24.17.0 and 24.18.1, the second shipped with 26.5.1.

  `engines.node` is `^24.18.1 || >=26.5.1`. That also excludes Node 25, which vitest 5 and tsdown
  0.23 no longer support.

No Dependabot ecosystem watches `packageManager` or `.nvmrc`, so neither would ever have been
proposed.

## tsdown 0.23, and what it did to the declarations

tsdown 0.23.0 pulls rolldown-plugin-dts 0.28, which since 0.28.2 changes the declaration shape:

- each value is exported where it is declared (`export declare function …`);
- the type-only names go in one `export type { … }`.

Packed before and after, the 12 tarballs hold the same 152 files:

| files          | changed | how                                                                 |
| -------------- | ------- | ------------------------------------------------------------------- |
| `*.js`         | 0 of 12 | byte-identical                                                      |
| `*.d.ts`       | 12      | the shape above; opc's 53 inline exports are its 53 runtime exports |
| `*.d.ts.map`   | 12      | follows the `.d.ts`                                                 |
| `*.js.map`     | 4       | geometry, opc, validate, xml: fewer `names`, same `sources`         |
| `package.json` | 12      | the packed `tsdown` devDependency version                           |

Every package gets a patch changeset, so npm serves what `main` builds.

**The website's reference would have gone blank.** `website/prerender/reference.mjs` read exports only
from `export { … }`, and nothing checked the other direction. It now:

- reads a declaration's own `export` modifier as an export;
- takes a type-only flag from the clause (`export type { A }`) as well as the element
  (`export { type A }`);
- strips `export` before `declare`.

It also holds each package to its runtime exports (`Object.keys(await import(pkg))`), and refuses:

- a type read as a value;
- a signature that still carries `export` or `declare`;
- any disagreement with the runtime exports.

Groups are ordered as they sit in the bundle, which is the same under either shape.

Measured:

- **Old shape**, the packages npm serves today: output identical, symbol for symbol, to the
  reference before this change.
- **New shape**, this commit's candidate tarballs through the candidate gate: byte-identical to the
  old shape's output.
- **Before the clause fix**, the new shape had marked 287 types as values, and the first form of the
  guard did not see it.

npm will serve both shapes at once until every package re-releases, which is why both paths stay.

## Verification

- `pnpm check` green.
- The candidate gate on this commit's tarballs green: provenance 12/12, typecheck, lint, test, smoke
  and build.
- `reference.mjs` mutants, 3 of 5 killed. Each of these fails the build on the new shape:
  - inline exports not read;
  - the clause's type-only flag ignored;

  Two survive:
  - **Removing the guard** is equivalent in isolation: it detects the other faults, and caught all
    three above.

    two shapes verified it.
