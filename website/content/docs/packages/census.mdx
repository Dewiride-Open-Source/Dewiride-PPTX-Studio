## What it is

`censusPackage` opens a deck and returns one JSON-safe object describing it: the archive, every part with its size and element count, the relationship graph, the presentation structure, a feature census keyed to the phase of the plan that draws each feature, the namespaces actually used, and any problems it met on the way.

It refuses nothing. A broken deck still gets a count, with the problem recorded beside it, which is what makes it the right thing to attach to a bug report.

## Key concepts

### Plain JSON on purpose

No `Map`, no class instance, nothing that would not survive `postMessage`. The census is meant to be computed in a Web Worker and handed back, and the CLI's `inspect` prints the very same object.

### Features by namespace, never by prefix

A chart is recognised by the namespace its element is bound to, not by the `c:` prefix a writer happened to choose, so a deck that spells its prefixes differently counts the same.

### Each feature names its phase

Every feature in the census carries the sub-phase of the plan that renders it, so the answer to "will this deck draw?" is in the census itself.
