## What it is

How a colour transform chain resolves, how a gradient is really blended, what a pattern tile looks like, how a dash is compensated for its cap, how a shadow's blur radius becomes a Gaussian sigma: none of that is in ECMA-376 in a form you can implement from. `@pptx-studio/paint` holds those rules as functions, and each one cites the fixture it was measured against.

## Key concepts

### Transforms apply in document order and clamp between steps

`lumMod` then `lumOff` is PowerPoint's "Lighter 40%"; the other order is a different, plausible, wrong colour. The 28 transforms are applied as written, clamping after each.

### Six colour spaces, one resolver

`srgb`, `scrgb`, `hsl`, `scheme`, `sys` and `prst` all resolve through `resolveColor`; a scheme colour needs the theme's scheme and the sheet's colour map, which the model package supplies.

### The two-colour gradient curve

PowerPoint does not blend two stops linearly. The measured curve is pre-sampled into a fifteen-knot ramp in a 2.2 power space, and every Office theme gradient has exactly that shape.

### Pattern tiles are physical size

The 54 patterns are 8-by-8 pixel tiles at 96 DPI and do not scale with the shape. They were transcoded from Mono's libgdiplus.

### Caps, joins, and the dash the cap eats

SVG adds a cap on top of a dash; PowerPoint paints the dash as ink. `dashArray` shortens each dash by a width and lengthens each gap by one so the ink matches.
